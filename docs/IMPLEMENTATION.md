# 实现与交付说明

## 范围

当前版本完成第一阶段可玩闭环：开始下降、手动连续油门、姿态调整、燃料消耗、接触与结果、重置和暂停。额外交付原创程序化 Blender 模型、GLB 资产与航天控制台风格界面。任务书中的第二至第五阶段属于后续目标，当前内容不能视为整套写实渲染计划已经完成。

实时逻辑全部在浏览器本地执行。静态服务器只分发 HTML、JavaScript、WASM、模型等文件，不参与控制或物理解算。

## 模块边界

`FlightPhysics` 无 DOM 或渲染依赖。`create()` 异步初始化 Rapier WASM，`reset()` 替换世界与初始状态，`advance(deltaSeconds, input)` 推进固定时间步，`snapshot()` 返回只读数据快照，`dispose()` 释放 WASM 世界与事件队列。

渲染读取快照中的火箭底点位置、四元数、实际油门与接地状态。视觉模型不参与碰撞求解，尾焰与音量读取实际油门。HUD 不参与物理积分。输入模块提供归一化目标油门与屏幕方向姿态量；`control-frame.ts` 依据当前摄像机水平朝向将姿态量转换为世界轴力矩输入。音频只有在用户点击声音按钮后创建与恢复 AudioContext。

`replay.ts` 通过 `interpolateSnapshot(a, b, t)` 在相邻录制快照之间生成显示帧，`t` 为两次采样间的归一化时间比例：位置、速度和遥测量线性插值，四元数沿最短路径球面插值并归一化；接地状态与结果测量到达后一快照时才切换。函数不修改录制数据，也不把插值结果反馈给物理模拟。插值已接入回放主循环，连续性、反号四元数与接地事件边界的纯函数测试已通过；本地浏览器已做初步功能检查，其他设备的观感与性能仍需验证。

模型以本地资产形式交付，导出脚本和源文件均在项目内。网页不依赖 Blender、不远程获取模型。Three.js 与 Rapier 版本已固定，升级依赖后应重新检查两个渲染后端与物理回归。

## 固定步长与力

- 内部采用 SI 单位，+Y 向上；重力 9.81 m/s²。
- 刚体固定步长 1/120 s，显示帧以累积器分配更新。物理模块单次 advance 的补偿时间限制为 0.25 s，应用入口进一步限制到 0.1 s，避免后台恢复时无限追帧，因此不会追算很长的后台间隔。
- 干质量 15,000 kg，燃料容量 9,000 kg，最大推力 550,000 N，最大耗油率 185 kg/s。这些是原创游戏参数。
- 发动机实际油门连续追随目标油门。街机变化率 0.9/s，真实感变化率 0.55/s；燃料耗尽则不再输出推力。
- 推力沿火箭机身上方向施加；阻力采用速度平方模型。燃料变化更新总质量；姿态通过简化控制力矩与可选稳定辅助调整。
- 无限燃料只在街机模式有效；真实感模式仍消耗有限燃料。

初始火箭底点为 (10, 98, 5) m，甲板 Y=3，因此离地高度为 95 m。质心近似位于模型底部上方 10 m。模型坐标与刚体坐标通过这一偏移连接。

## 接触与结果

平台为 44×44 m，甲板上表面 Y=3。Rapier 的简化机身与四脚碰撞体负责接触事件，不使用仅比较高度的假接地。四脚均需落在甲板内，且着陆脚先触地；垂直速度、水平速度与倾角也须满足模式阈值。

| 模式 | 垂直速度上限 | 水平速度上限 | 倾角上限 |
| --- | --- | --- | --- |
| 街机 | 3 m/s | 2 m/s | 10° |
| 真实感 | 1.8 m/s | 1 m/s | 5° |

落海、边缘接触、机身接触以及超限触地会失败。接地后记录结果并清零推力、速度和外力。成功着陆会归正并放置于甲板，避免静止后小幅抖动；因此当前版本并非接地后持续滚动、倾覆或破碎的物理模拟。

## 输入与声音

Space 以约 0.7/s 增加目标油门，松开后约 0.45/s 下降；手动拖动滑块则保持选定目标。W/S 沿当前摄像机水平前/后方向调整姿态，A/D 沿当前摄像机左/右方向调整姿态；摇杆使用相同参考系。转动或切换镜头后，控制方向随视角改变。触摸摇杆使用指针捕获，在结束、取消或失去焦点时回中。输入监听器在释放时逐一解绑。

摄像机朝向约定为 `yaw = atan2(forward.x, forward.z)`；水平前向为 `(sin(yaw), cos(yaw))`，右向为 `(-cos(yaw), sin(yaw))`，均按世界 X/Z 排列。组合方向归一到最大单位长度，避免对角线输入放大姿态控制量。物理模块正 pitch 将推力转向 +Z，正 roll 转向 −X；映射函数按这一符号约定转换。近乎竖直的俯视方向保留上一有效水平朝向，避免投影过小导致方向翻转。姿态指令仍通过刚体旋转影响推力方向，不直接改变水平位置或消除惯性。

Web Audio 使用缓冲噪声与低频振荡器，经低通滤波和增益平滑合成引擎声，不下载外部音频。声音仅在主动点击后开启，关闭时降低增益；退出时停止音源、断开节点并关闭上下文。平台附近仅调整合成声音强弱，不声称采用真实发动机声学模型。

## 图形与资产

默认优先尝试 WebGPU；能力不足或初始化失败时回退 WebGL2。实际后端显示在性能区，WebGPU 不是性能保证。启动成功只证明当前设备路径可用，不能代替对所有浏览器和驱动的兼容性验证。

原创模型由 Blender Python 自动生成，保留 `.blend` 与 `.glb`。火箭底点 Y=0，高约 20 m，平台甲板 Y=3；Blender 的 Z-up 在 glTF 导出时转换为 Y-up。PBR 材质区分涂层、金属、隔热区域和甲板；程序化几何承担面板、栅格翼与工业设施细节。几何规模记录于 `assets/model_metrics.json`，重新生成后会更新。

本轮已实现近景跟随与自由轨道的拖拽、缩放；镜头水平朝向用于同步姿态输入。模型动态视觉包括 8 个 RCS 喷口、主喷口偏转、激波尾焰、4 片格栅翼以及着陆腿；着陆腿在甲板上方 40 m 内全展开。上述反馈属于游戏化视觉层，刚体仍由简化力与力矩推进，不等同于真实航天器执行机构或喷流耦合模型。

本地桌面浏览器已完成这些功能的初步检查，390×844 与 844×390 视口布局未出现溢出；实体手机触控、不同显卡效果与持续运行性能尚未实测。

资源生成脚本可重现所有运行时模型，具体命令见 README。用户不需要安装 Blender 即可运行游戏；开发环境使用已有 Blender，不更改驱动、功耗或系统设置。

## 验证方法

自动化物理测试使用 Node 原生测试运行器和 tsx，不需要浏览器或显卡。测试覆盖固定步长在 30/60/144 FPS 输入下的一致性、重力、推力、燃料、发动机变化率、姿态、接触和阈值、五分钟固定步长运行、重复重置和释放。`control-frame.test.ts` 另覆盖四个主方向与斜向摄像机、组合键归一化、模拟量幅度、退化视角保护，并以 Rapier 实际加速度验证 W/D 的镜头相对方向。

本轮 26 项回归测试与 `build.cmd` 已通过，构建包含 TypeScript 严格检查和 Vite 静态打包。回放测试额外覆盖连续量、最短路径四元数与离散接地事件。本地浏览器已进行初步功能与横竖视口布局检查；详见 `docs/TESTING.md`。实体设备触控、不同后端与显卡组合、功耗和长时 GPU 稳定性仍需独立验证，没有实测的数据不列为已验证硬件性能。

可靠的 CPU 帧时间和物理耗时可以通过浏览器计时获取，绘制调用与几何统计可以从渲染器获取。GPU 时间只有在可用的可靠计时接口下才有意义；当前不输出 GPU 利用率、显存占用或编造的 GPU 时间。

## 尚未覆盖的高阶需求

AO、Bloom、景深、热扭曲、完整反射后处理与 PWA 缓存尚未实现。当前没有真实风场、柔性结构、发动机簇故障、多体结构破坏、真实飞控参数，也没有覆盖所有设备的 GPU 基准测试。长期稳定性测试针对五分钟物理更新与重复资源释放，不等同于多小时浏览器 GPU 内存测试。

部署为静态 `dist/`，可上传 GitHub Pages 或其他 HTTP(S) 静态主机。相对 `base: './'` 允许仓库子路径；发布后应在目标路径验证 GLB 与 WASM 资源请求。

`.github/workflows/pages.yml` 在 `main` 推送或手动触发时安装固定依赖、执行测试与构建，然后使用 Pages artifact 部署。[源码仓库](https://github.com/unowhatpvp-alt/rocket-landing-simulator) 已创建，Pages 发布源已保存为 GitHub Actions，工作流具备 Pages 写权限与 OIDC 令牌权限。[线上地址](https://unowhatpvp-alt.github.io/rocket-landing-simulator/) 已完成首次部署：GitHub Actions 构建和部署成功，线上 WebGPU 点火验证通过，HTML 与 GLB 资源返回 200。流程依据 [GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。游戏运行仍不依赖账号、数据库或远程物理服务。
